# AI 키우기 — 제품 문서

문제 정의, 가설, 백로그, 스프린트, 회고를 이 한 파일에 둔다. 작업 상세 기록은 `WORKLOG.md`.
버그 수정처럼 기획이 필요 없는 일은 여기 거치지 않는다.

## 오늘 메모 (작업 시작 전 세 줄)

- 어제 한 것: 스프린트 2.5 벤치마크 (잘된 방치형 18개 리뷰로 평가표, 자동 구매, 밸런스 다시 맞춤)
- 오늘 할 것: 의견 받을 구글 폼 정하기 → 비공개 테스트 시작 (스프린트 3)
- 막힌 것: Play Console 신원 확인(주소 서류)·폼 주소 (만든 사람이 할 일)

## 1. 문제 정의

**대상** (가정, 친구 테스트로 확인할 것)
- 주 대상: AI 이야기는 매일 듣지만 어떻게 여기까지 왔는지는 모르는 20~30대. 폰으로 틈틈이 게임을 한다.
- 부 대상: 방치형 게임을 원래 좋아하는 사람.

**문제 인식**
- AI 역사는 공부하려면 딱딱하고, 방치형 게임은 숫자만 커져서 금방 질린다.

**원하는 것 / 기대하는 것**
- 출퇴근 5분씩 가볍게 켜서 성장하는 맛을 느끼고, 하다 보면 "아 이게 이렇게 된 거구나"를 알게 되는 것.

**관찰되는 현상** (지금까지 모은 것. 실제 플레이어 데이터는 아직 없음)
- 만든 사람이 직접 해 본 피드백(20차): "가시성이 떨어지고 뭐가 뭔지 모르겠다, 너무 복잡하다."
- 봇 플레이(12차): 시대 3에서 보스 11번 도전 11번 패배, 화면이 실패 알림으로 덮임.
- 자체 플레이 기준선(스프린트 1, 아래 5절).

**기대 효과 (지표)**
| 지표 | 무엇을 보나 | 어디서 보나 |
|---|---|---|
| M1 첫 세션 시대 3 도달 비율 | 처음 10~15분 안에 게임을 '이해'했는가 | 시대 3 타임어택 랭킹 참가자 수 ÷ 설치 수, 친구 테스트 관찰 |
| M2 다음 날 다시 켠 비율 (D1) | 다시 하고 싶은가 | Play Console 통계, 친구 테스트 설문 |
| M3 "헷갈렸다" 피드백 비율 | 복잡함 문제가 줄었는가 | 의견 보내기, 테스트 후 질문 |
| M4 엔딩 도달 비율 | 끝까지 재미가 이어지는가 | 시대 10 타임어택 랭킹 참가자 수 |

개인정보를 모으지 않는 원칙은 지킨다. 분석 SDK를 넣지 않고 위 네 군데에서만 본다.
랭킹 화면은 참가자 수를 보여 주므로 시대별 타임어택 랭킹이 그대로 "시대 N까지 간 사람 수" 퍼널이 된다.

## 2. 가설

- **H1 (이해)**: 쉬운 말 + 새 기능 소개 + 도움말을 넣으면, 친구 테스터 중 "뭐가 뭔지 모르겠다"고 답하는 비율이 절반 이하가 되고 70% 이상이 첫 세션에 시대 3에 간다.
- **H2 (재방문)**: 오프라인 보상 + 파견 복귀 알림이 있으면 D1이 40% 이상이다.
- **H3 (안내만으로 진행)**: 화면 안내('다음 할 일' 칩과 추천 줄)만 따라 해도 막힘 없이 시대 3에 간다. (자체 측정 가능: 아래 초보 봇)

숫자는 기준선이 없어서 정한 첫 목표다. 첫 측정 뒤 다시 맞춘다.

## 3. MVP 범위와 백로그

**MVP = 지금 빌드에서 기능 동결.** 가설 검증(친구 테스트)에 새 기능은 필요 없다.
스프린트 동안 하는 일은 측정에서 나온 문제를 고치는 것뿐이다.

**백로그** (가치 대비 노력 순, 측정 결과로 다시 정렬)
| 항목 | 크기 | 비고 |
|---|---|---|
| 테스터 설문 3문항을 의견 보내기 창에 넣기 | S | 의견 받을 곳(폼) 정해지면 |
| 시대별 진행 퍼널 기록표(랭킹 참가자 수 주 1회 기록) | S | 출시 후 |
| 새 시대·콘텐츠 추가 | L → 쪼갤 것 | 엔딩 도달 비율(M4) 보고 결정 |
| 보상형 광고·결제 | L | 무료판 원칙. 상업화 결정 전엔 안 함 |
| 판매판(실존 이름 정리) | L | 상업화 결정 전엔 안 함 |

## 4. 에픽 → 피처 → 유저 스토리

**에픽 A. 처음 15분 안에 이해한다**
- 피처 A1 안내 따라가기
  - 스토리: 처음 하는 사람으로서, 나는 화면이 가리키는 것만 눌러도 앞으로 나가고 싶다. 왜냐하면 규칙을 읽고 싶지 않기 때문이다. (M)
  - 인수 조건: 초보 봇(안내 칩 + 추천 줄만 누름)이 15분 안에 시대 3 도달 / 안내 탭에 살 게 없는 '막힘' 시간이 전체의 20% 이하 → **통과 (스프린트 1)**
- 피처 A2 창 줄이기
  - 스토리: 처음 하는 사람으로서, 나는 창이 연달아 떠서 흐름이 끊기지 않았으면 한다. 왜냐하면 무엇을 누르던 중인지 잊기 때문이다. (S)
  - 인수 조건: 첫 10분 창 10개 이하, 같은 창이 30초 안에 두 번 뜨지 않음 → **통과 (스프린트 2, 15개 → 10개)**

**에픽 B. 다음 날 다시 켠다**
- 피처 B1 돌아온 보상
  - 스토리: 바쁜 사람으로서, 나는 하루 뒤 켰을 때 쌓인 보상과 할 일을 바로 보고 싶다. 왜냐하면 짧게 하고 끄기 때문이다. (S)
  - 인수 조건: 오프라인 보상 창 → 다음 할 일 칩이 바로 보임 → **통과 (스프린트 2, 창 1개 뒤 바로 칩. 알림이 돈 숫자를 가리던 것 고침)**

**에픽 C. 피드백을 모은다**
- 피처 C1 의견 보내기 (완료, 21차)
- 피처 C2 랭킹 참가자 수 (완료, 스프린트 1)
  - 스토리: 만든 사람으로서, 나는 시대별로 몇 명이 도달했는지 보고 싶다. 왜냐하면 어디서 그만두는지 알아야 고치기 때문이다. (S)
  - 인수 조건: 랭킹 화면에 '참가 N명', 모르면 표시 안 함

## 5. 스프린트

(스프린트마다 목표 · 결과 · 측정 · 회고를 쌓는다)

**측정 도구** (실제 사람 대신 쓰는 대리 지표. 진짜 판단은 스프린트 3의 친구 테스트로)
- 초보 봇: '다음 할 일' 칩을 누르고, 표시된(추천) 줄과 '연구 가능' 칸만 산다. 보스는 칩이 가리킬 때만, 보스전에선 빠르게 탭.
  - 브라우저판(실제 화면을 누름, 10~20분): 시대 도달 시각, 아무것도 못 한 시간, 창 개수와 제목
  - 코어판 `npm run novice` (3초에 처음~엔딩): `npm test`에 넣어 시대 3을 15분 안에 못 가면 실패
- 숙련 봇(살 수 있는 건 다 사고 바로 도전): 바꾼 것이 잘하는 사람을 느리게 하지 않는지
- 다음 날 복귀(8시간 전 세이브): 뜨는 창과 닫은 뒤 첫 화면

### 스프린트 0 (회고): 1~21차, 10/8~10/15

- 한 것: 11개 시대 게임 전체, 안드로이드 앱, 꾸미기·뽑기·랭킹·무한 모드·도움말·의견 보내기.
- 잘된 점: 매번 동작하는 결과물, 테스트·번역·접근성 자동 검사, 작업 기록.
- 아쉬운 점: 문제·가설 없이 기능 요청부터 만들었다. 실제 사람 플레이 0회. 효과를 잴 수단도 기준선도 없었다.
- 바꿀 점: 이 문서로 문제 → 가설 → 측정 → 수정 순서를 지킨다. 새 기능은 백로그로.

### 스프린트 2: 첫 10분 창 줄이기 + 다음 날 돌아왔을 때 (에픽 A2, B1)

- 첫 10분 창 **15개 → 10개**: 퀴즈는 10분 플레이 뒤부터(퀴즈 1번 = 문제 창 + 결과 창), AI 겨울은 시대 전환 창 안에 같이(같은 초에 창 2개 → 1개), '새 모델 출시'·'랭킹' 소개는 시대 4부터(처음 10분엔 쓸 일 없음).
- 다음 날 복귀: 창 1개(자리 비운 동안 보상) → 닫으면 바로 안내 칩. 다만 출석·업적 알림이 머리말을 덮어 **돈 숫자가 안 보였다** → 알림을 머리말 바로 아래로.
- 접근성 검사(시대 0·3·6·9·10) 위반 0, 테스트 통과.

회고
- 잘된 점: 창 제목을 시간순으로 뽑아 보니 무엇을 줄일지 바로 보였다.
- 아쉬운 점: 퀴즈를 미룬 건 '처음 10분엔 배울 게 많다'는 추측이다. 친구 테스트에서 퀴즈 반응을 따로 물어볼 것.

### 스프린트 2.5: 잘된 게임 기준으로 평가 (10/18)

문제: 우리 기준(봇·안내)만으로는 '게이머가 실제로 싫어하는 것'을 놓칠 수 있다.
방법: 잘된 방치형 18개의 Steam 리뷰 약 5,000개에서 칭찬·불평 주제를 세어 평가 기준 C1~C11을 만들고(`tools/review-insights/`), `npm run scorecard`로 잰다. 자세한 건 `docs/BENCHMARK.md`.

- 부족 2개: 자동화 없음(C3), 손 부담(C2: 엔딩까지 건물 약 5,500개를 손으로). 주의 1개: 수입 10배까지 20분 구간(C10).
- 한 것: 시대 3부터 자동 구매(3단계). 넣고 보니 엔딩이 42~52분으로 빨라져 원인을 재 봤더니, **기존 밸런스가 '1초에 하나만 사는 봇' 기준**이어서 꾹 누르기로 버는 만큼 사는 사람은 원래도 1시간 안에 끝났다. 그래서 '버는 만큼 쓰는 사람' 기준으로 시대 3부터 다시 맞춤, 출시 보너스 절반, 자동 구매 몫 15%, 특이점 너머 시작 한 칸 뒤로.
- 결과: 평가표 12개 항목 모두 통과. 사람형 봇 엔딩 1h27m(손으로도 삼)·1h30m(자동 구매에 맡김), 초보 1h46m, 40분 넘는 정체 0.

회고
- 잘된 점: 남의 리뷰 5,000개가 우리 봇 수백 판보다 빨리 '어디를 봐야 하는지' 알려 줬다(자동화). 그걸 넣으면서 밸런스 기준 자체가 틀렸다는 더 큰 문제를 찾았다.
- 아쉬운 점: 사람형 봇 한 판(씨앗 42)만 보고 '시대 7 벽'이라 판단했다가, 7판 중앙값으로 보니 우연이었다. → 평가표는 여러 판 중앙값으로 바꿈.
- 바꿀 점: 밸런스를 바꿀 땐 `npm run scorecard`와 `npm run playtest`(두 플레이어 모델)를 같이 본다.

### 스프린트 2.6: 차분한 시대 디자인 + 재난·바이러스 + 잃어버린 기술 + 버튼 설명 (10/20)

### 스프린트 2.7: 첫 1분 훅 (10/20)

문제(만든 사람 피드백): 딱딱하고 거부감. 관찰: 놀기 전 글 창 2개, 첫 구매가 수입을 못 올림(+0.08/초 그대로), 8·22초에 또 창.
가설: 첫 행동 전 글을 없애고 첫 구매가 바로 수입을 몇 배로 올리면, 친구 테스트에서 '첫 5분 안에 그만두고 싶었다' 답이 줄어든다(H1 보조).
한 것: 창 없이 시작(제목 한 줄), 첫 질문 헛소리 개그 → 바로잡기, 첫 구매 계산기로 ×2 → ×4, 처음 90초 소개 창 없음, 도트 UI 따뜻하게. 결과: 첫 6초 창 0개·수입 ×5.
회고: 첫 1분을 직접 기록해 보니 '튜토리얼이 엉뚱한 걸 사게 한다'가 바로 보였다. 시대마다 병목이 바뀌므로 튜토리얼 대상도 '그때 병목'을 따라야 한다.
